# Keppel DC REIT Research — Vercel front-end

Next.js (Pages Router) + TypeScript + Tailwind. Replaces the Streamlit UI in
`002-KDC-RAG/app.py` (now archived under `_streamlit_archive/`).

## Architecture

```
[ Browser ]
   ↓
pages/index.tsx ─── Sidebar (corpus stats · doc-type filter · price · examples)
                ┕── Conversation (research-note answers + cited sources)
   ↓
GET  /api/stats   → corpus stats for the sidebar
GET  /api/price   → AJBU.SI monthly OHLC (Yahoo Finance, cached on edge)
POST /api/chat    → HyDE → embed → hybrid retrieve → Anthropic Claude → cited answer
   ↓
lib/retriever.ts  ─── reads web/data/chunks.json + web/data/embeddings.bin
                       once per cold start, then serves all queries from memory
```

The retrieval logic is a TypeScript port of `RAGEngine` in `rag.py`:
HyDE-blended OpenAI embeddings, hybrid dense + BM25 with Reciprocal Rank Fusion,
optional doc-type filter, and the same source-trust system prompt for Claude.

## Local dev

```bash
cd 002-KDC-RAG/web
cp .env.example .env.local      # paste real ANTHROPIC_API_KEY + OPENAI_API_KEY
npm install
npm run dev                     # http://localhost:3000
```

The API route reads `web/data/chunks.json` + `web/data/embeddings.bin`. To
regenerate those from the Python pipeline:

```bash
cd 002-KDC-RAG
python ingest.py                # rebuilds index/faiss.index + index/metadata.json
cd web/scripts
python export-index.py          # writes ../data/chunks.json + ../data/embeddings.bin
```

`export-index.py` is a thin converter — it reconstructs the vectors from the
FAISS index and writes them as a flat `Float32Array` so the TS retriever can
mmap them with no decoding step.

## Deploy to Vercel

1. Push the `002-KDC-RAG` folder to GitHub.
2. In Vercel: **Add New… → Project → Import** the repo.
3. **Settings → General → Root Directory** → `web` (this is the magic that
   makes Vercel ignore the Python pipeline at the parent level).
4. **Framework Preset** → Next.js (auto-detected).
5. **Settings → Environment Variables** → add `ANTHROPIC_API_KEY` and
   `OPENAI_API_KEY` (Production + Preview).
6. Push to main / click **Deploy**.

If Vercel misdetects the project as Python, see
`_orikai_playbooks/vercel-deployment-troubleshooting.md` Failure 1.

## Pre-deploy checklist

```bash
# From 002-KDC-RAG/
ls -la | grep -E "runtime\.txt|app\.py|\.streamlit|\.devcontainer"
# Expected: no app.py, no .streamlit/, no runtime.txt at the root.

grep -E "^(lib|build|dist|env|venv)/$" .gitignore
# Expected: nothing — anything found should be prefixed with /

cd web && npx tsc --noEmit && npx next lint --dir pages --dir components --dir lib
cat vercel.json
# Expected: {"$schema": "...", "framework": "nextjs"} — no functions block
```

## Differences from the Streamlit version (intentional)

- **No login gate / Google Sheets signup.** Vercel can gate access via a
  password (Project Settings → Deployment Protection) if needed; that keeps
  the UI focused on the research surface.
- **Stateless conversation.** The Streamlit app held history in
  `st.session_state`; here it lives in React state. Refresh = new session.
- **Cited-research-note styling instead of chat bubbles.** The assistant
  output renders as a memo (Source Serif body, IBM Plex Mono labels) with
  inline `[n]` chips that scroll the matching source row open.
- **HyDE, hybrid retrieval, and price context are unchanged.** Same models,
  same prompts, same RRF parameters as `rag.py`.
